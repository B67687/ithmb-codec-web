### F-001: Navigation Bar (`src/nav.ts` → `assets/js/nav.js`)

- **Status:** applied
- **Reviewed:** 2026-11-27

**Behavior Contract:** Preconditions: any page. The nav is rendered into the HTML at build time by `src/shell.ts`; `src/nav.ts` binds to that markup (no runtime injection, so no-JS visitors and crawlers get the links). Postconditions: fixed top nav (48px, glass), brand, theme toggle with `aria-pressed`, language controls, BMC and GitHub links. Active link comes from `pathname` with the zh prefix stripped and is marked `aria-current="page"`; the notices page is a paired EN/ZH page and carries the same language controls as the rest of the site, and the privacy/404 pages do not mark a false current item. Theme: `theme.ts` sets `data-theme` pre-paint; an explicit choice is persisted in `localStorage ithmbTheme` and pinned against later OS changes, while no stored choice follows OS changes live. Language: switching persists `ithmbLang` before the plain-link navigation; direct URLs always win (the old `lang-redirect` no-op is gone). With decoded files loaded, the switch opens a confirm dialog, and cancelling leaves the preference untouched. Mobile drawer: real `<button>` with `aria-expanded`/`aria-controls`, scrim, focus moves to the first link, Escape/scrim/link close and restore focus; drawer opening locks background scroll and closing restores the exact position.

### F-006: File Drop/Upload Flow

- **Status:** applied
- **Reviewed:** 2026-11-27

**Behavior Contract:** Preconditions: decoder page loaded; drops that arrive while WASM initialises queue instead of failing. Postconditions: a drop, the file picker and the "Try a sample" button all funnel into `processFiles(files)`. The first batch of a session resets the card list, counters, result lists, filmstrip, viewer and dedupe set; every batch then accepts only `.ithmb`/`.ipm` names (case-insensitive) at ≤ 8 MB, dedupes on lowercase name + full-file SHA-256, and enforces the per-session caps of 200 files / 256 MB (a file whose `File` read fails skips the fingerprint and is reported per card instead of aborting the batch). Skips are aggregated into one persistent `#batchNotice` summary — accepted plus not-.ithmb/.ipm, over 8 MB, duplicate, over the file cap, over the byte cap, folder drops — with a dismiss button and a live-region announcement, instead of stacked toasts. Accepted files get one card each, decode in waves of four, the viewer opens on the first result, progress is announced ("Decoding N file(s)…" → "Decoded N image(s)…"), and the toolbar updates after each settle and after the batch. Invariants: one dedupe key per unique file; rejected files never take a session slot; a directory drop is reported, not silently walked. Error cases: unsupported, oversized, duplicate or over-cap files are skipped and counted in the summary, not decoded.

### F-007: Decode Pipeline (`decodeFile`)

- **Status:** applied
- **Reviewed:** 2026-08-27

**Behavior Contract:** Preconditions: valid file input. Postconditions: read → Uint8Array → `planDecode` (pure, DOM-free) → `decode_ithmb`; success → canvas rendered to at most 600×400 CSS size → success card (with `JPEG (embedded)` for a JPEG stream and a `Frame: 1 / N` row when a multi-frame payload was clipped); failure (known/unknown/database) → failure card with failure info; a throw after bytes/prefix were captured (wasm panic, OOM, malformed pixel header) also renders the failure card; only pre-bytes failures (empty or unreadable file) render an error card (message only, NOT pushed to failedDecodes). Invariants: an unknown prefix that matches the codec's 256-byte size heuristic is refused before WASM (MT-003); a multi-frame payload is clipped to frame 0 before WASM (MT-004); a guessed/failed decode never enables Save or ZIP; error cards never stored (they carry no decodable bytes); updateToolbar() called after each decode. Error cases: wasm throw before bytes → error card.

### F-018: Decode Pipeline Unit Logic

- **Status:** applied
- **Reviewed:** 2026-11-27

**Behavior Contract:** Preconditions: raw file bytes, no DOM and no WASM (the module is what makes the branch decisions importable from node/bun-scoped tests). Postconditions: `peekPrefix` reads the 4-byte big-endian format number and returns 0 for a slice shorter than 4 bytes. `planDecode(bytes)` returns `decode` (the bytes to hand to WASM, a JPEG flag and optional frame info) or `reject` (mode damaged/unknown/database) in this order: shorter than 4 bytes → damaged; `mhfd`/`mhbd`/`mhif` magic → database; a JPEG SOI stream → decode as an embedded JPEG; a known prefix → decode; an unknown non-JPEG prefix → refused as unknown when its payload length (`bytes.length - 4`) sits inside the codec's 256-byte trailing-padding window of any profile's `frameBytes` (`heuristicWouldMatch`), otherwise kept for the codec's validated SOI..EOI carve path with `jpeg: true`. `pickFrame(prefix, dataLen)` clips a known-prefix payload to frame 0 once it exceeds one stride plus the 256-byte tolerance: the candidates are the profile's `frameStride` plus the Nano 7G alternates, the largest exact multiple wins (falling back to the largest fitting stride), `total` is null when the length is not an exact multiple, and the returned input is `bytes.subarray(0, 4 + stride)`; a clipped frame is never labelled JPEG. `classifyFailure(bytes, prefix)` maps database magic → database, a JPEG SOI or a payload under 16 bytes → damaged, a known prefix → damaged, and anything else → unknown. `classifyResult(prefix, result)` keeps the legacy success/known-failed/unknown branch contract, and `parsePixelHeader(result)` reads little-endian width/height at offsets 0 and 4 and slices the pixels at offset 8. Invariants: the module is DOM-free; the profile table is generated (53 entries, 1044 absent); an unknown prefix that the size heuristic would match never reaches WASM (MT-003); a multi-frame payload never reaches WASM unclipped (MT-004). Error cases: zero dimensions parse without throwing; empty or short input classifies as damaged.

### F-030: Decoder Data Integrity (B3)

- **Status:** applied
- **Reviewed:** 2026-11-25

**Behavior Contract:** Preconditions: user drops .ithmb/.ipm files (≤ 8 MB each). Postconditions: the decoder never paints a guess as a success. (1) An unknown 4-byte prefix whose payload length lands within 256 bytes of a codec profile is refused with the "Unknown format" failure card and no Save/ZIP (MT-003, F1/F4); an unknown prefix with no size match keeps the validated embedded-JPEG carve path and is labelled `JPEG (embedded)`. (2) A payload longer than one frame is clipped to the profile's frame stride (slot_size for padded profiles, Nano 7G alternates honoured); the visible status reads `Decoded: W × H · frame 1 of N` (or `frame 1 of ?` when the container is truncated) and an info row carries `Frame: 1 / N`, so RGB565/RGB555 frame 0 matches the Rust CLI pixel-for-pixel (MT-004, F2). (3) Dedupe fingerprints the whole file with SHA-256 keyed by lowercase filename: two different files that share a name and their first 256 bytes become two cards, identical files still dedupe (MT-017, F6). (4) Failure classification uses the generated 53-profile table (prefix 1044 is absent upstream) and a JPEG SOI that fails is "damaged", not "unknown" (F5/F7). Invariants: the profile table is generated by `scripts/gen-profile-table.mts` from `ithmb-codec/crates/ithmb-core/data/profiles.json` and the unit tests pin the 53-prefix set; Save/ZIP only ever include decodes whose frame 0 was validated against the CLI reference. Error cases: database magic → database card; empty/short input → damaged.
