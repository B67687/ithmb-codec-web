# 中文文案风格

面向 ITHMB Codec 中文页面的写作规范。目标不是“字面忠实”，而是让中文读者读起来像中文：先还原意思，再用中文说。术语准确优先于口语化，但不要为了“正式”写成公文。

适用页面：`/zh/` 首页、解码器、指南、隐私、404，以及解码器动态文案、aria-label、meta 和 JSON-LD。

## 1. 总则

- 同一页面只用一种语域：营销页可以轻快，隐私页必须稳。
- 一句话只做一件事。超过 35 字就考虑拆句。
- 能补出主语。中文可以省主语，但承诺句、权利句、法律句必须能补出“谁对谁做什么”。
- 先写中文，再对英文。不要照着英文语序填词。

## 2. 人称与语气

- 统一用“你”，不要混用“您”。全站不要出现“用户”“访客”来指代读者，除非是法律定义。
- 首页/解码器：短句、动词开头，允许“就、也、都、多半、就行”。
- 指南：说明文，步骤用祈使句；技术名词第一次出现时解释。
- 隐私/条款：中性书面，不用“跑、搞定、搬走、抄进、挡攻击、送到你面前”；也不要用“兹、特此、予以”。
- 不要在隐私页里一半律师、一半产品经理。

## 3. 动词搭配

| 不要写 | 写成 | 原因 |
|---|---|---|
| 打开磁盘使用 | 启用“磁盘使用” | 设置项用“启用” |
| 打包 ZIP / 打成 ZIP | 打包成 ZIP | 动词需要结果补语 |
| 写成 PNG | 导出为 PNG / 保存为 PNG | “写”用于文件内容，不用于格式转换 |
| 基于 MIT 许可证开源 | 以 MIT 许可证开源 | open-sourced under 的中文说法 |
| 适用各自的许可证 | 遵循各自的许可证 | “适用……许可证”搭配不成立 |
| 嵌入 Cookie | 设置 Cookie | Cookie 不是嵌入的 |
| 送达页面 | 提供网页 / 返回页面 | deliver pages 的直译 |
| 保持可用安全 | 保障服务可用与安全 | 两个意思不能硬拼成一个动宾 |
| 抄进系统 | 复制到我们的系统 | “抄”不用于数据复制 |
| 提 issue 和格式样本 | 提交 issue，并提供格式样本 | 两个宾语需要两个动词 |
| 认不出你的请求 | 无法对应到你的请求 | identify 不是“认” |
| 数据发过去 | 数据发送给对方 | send over 的直译 |
| 打开缩略图 | 查看缩略图 | 打开文件，查看图片 |
| 取回图片 | 导出图片 / 保存图片 | “取回”用于失物 |
| 恢复照片（当做不到时） | 提取缩略图 / 查看缩略图 | 不要承诺恢复原图 |
| 只读文件 | 只读取文件，不会修改 | 避免 read-only 歧义 |
| 加统计 | 添加统计 | 书面文案用“添加” |
| 让项目看看 | 交给维护者查看 | 项目不会“看” |
| 支持开发 | 支持这个项目 | “支持开发”指向不清 |
| 同意横幅 | 同意弹窗 / Cookie 横幅 | consent banner 的常用中文 |

## 4. 介词框架

| 框架 | 用途 | 例子 |
|---|---|---|
| 由 + 施事 + 动词 | 强调责任主体 | 由 Cloudflare 托管 |
| 在 + 平台 + 上 | 强调技术位置 | 托管在 Cloudflare Pages 上 |
| 用 + 工具/方式 | 手段 | 用桌面工具打开 |
| 通过 + 渠道 | 路径 | 通过 GitHub 反馈 |
| 对 + 对象 | 影响 | 对隐私的影响 |
| 关于 / 针对 | 话题 | 关于 ITHMB 文件 |
| 基于 + 事实/标准 | 依据 | 基于 MIT 许可证 |
| 用于 + 目的 | 用途 | 用于排查传输错误 |
| 在……中 / 里 | 范围 | 在浏览器中运行（书面）/ 在浏览器里跑（口语） |

`托管在 + 公司名` 不要单独用：补“上”，或改成“由……托管”。`基于 + 许可证` 可以，但“开源”要用“以……许可证开源”。

## 5. 量词与数量

- 文件：个；图片：张；格式/编码：种；步骤：个；截图：张；帧：帧；导入：次；记录：条；问题/issue：个。
- `200 个文件、共 256 MB` → `200 个文件，合计 256 MB`。两个上限分开说。
- 数字和单位之间加空格：8 MB、256 MB、320 × 320。中文量词前不加空格：3 张图、2 种编码。
- `第 1 帧，共 N 帧` 全站统一；正文写“第 1 张，共 3 张”，UI 里的 `1 / 3` 可以保留。
- 不要用“枚、只、份”来数文件；不要把“一个文件一张图”压成“每文件一图”。

## 6. 中英混排与格式

- 汉字与英文/数字之间加空格，保持。
- 中文里表示“或/和”时优先用顿号或“或”；语言切换的 `EN / 中` 可以保留斜杠，但三处写法要统一。
- 产品名和格式名保持原样：.ithmb、.ipm、JPEG、PNG、BMP、WebP、PhotoData、PhotoDB、ArtworkDB、iPod nano、iPod Classic、iPhone、macOS、localStorage、User-Agent、Cloudflare Pages、Buy Me a Coffee、MIT。不要翻译代码、路径、命令。
- 首次出现的英文缩写给中文：网络错误报告（NEL）。
- 中文句子里的括号用全角；纯英文短语内部用半角。
- 品牌大小写：ITHMB Codec（站名）、Ithmb-Codec（仓库/桌面工具）、ithmb-core（库）。

## 7. 标点

- 中文句子用全角标点，句末用“。”；不要把英文句号带进中文句子。
- 并列用顿号，最后两项可用“和/与”；列表项末不加句号，除非是完整句。
- 引号用“”；按钮名、菜单项名也用“”，例如“打包下载”。
- 图注写“图 1：……”或“图 1　……”，不要写“图 1。”。
- 正文引用章节写“第 3 节”，`03` 只作为目录/标题的视觉编号。
- 破折号用“——”，省略号用“……”，范围号全站二选一（8–256 MB 或 8～256 MB）。

## 8. 句法：去翻译腔

- 去名词化：the processing of data → 处理数据；the delivery of pages → 提供网页；application data → 使用数据。
- 去被动：files are not uploaded → 文件不会上传；the site is hosted by → 本站由……托管（这个“由”是汉语自然框架，可以保留）。
- 拆长定语：超过 20 字的定语就拆句。`文件里直接带图像数据的 .ithmb 和 .ipm` 不要整块放在主语位置，先说“网页版只支持……”，再补条件。
- 补主语：承诺句、权利句、法律句必须能补出主语。`我们收不到，也不用来识别你` 要补成“我们不会收到这些报告，也不会用它们识别你的身份”。
- 少用虚动词：进行解码 → 解码；作出确认 → 确认；给予支持 → 支持。
- 少用“的的不休”：一句话里两个“的”就考虑拆句。
- 少用“被”字句；能用意义被动就用意义被动。
- 语序按“时间 → 地点 → 方式 → 动词”；“把”字句适合处理对象；“先……再……”要有真实先后关系。
- 避免英文同位语堆叠：`PhotoData slots and PhotoDB or ArtworkDB database files` → “PhotoData 里的槽位，以及 PhotoDB 或 ArtworkDB 数据库文件”。

## 9. 语域分层

| 页面 | 语域 | 可以用 | 不要用 |
|---|---|---|---|
| 首页 | 轻营销、口语 | 你、就、也、多半、不用安装 | 兹、特此、予以 |
| 解码器 | 工具界面、短句 | 解好了、没解开、重试、拖入 | 进行解码、解码失败（除非错误码） |
| 指南 | 说明文、步骤 | 你需要什么、你会看到、出问题怎么办 | 首先、其次、综上所述 |
| 隐私/条款 | 中性书面 | 我们、你、法律依据、正当利益、数据处理者 | 跑、搞定、搬走、抄进、挡攻击、送到你面前 |

## 10. 站内术语表

| 术语 | 统一写法 | 不要写 | 备注 |
|---|---|---|---|
| 文件格式 | .ithmb / .ipm | ITHMB 文件格式（指格式时可用“ITHMB 格式”） | 小写、带点 |
| 解码器 | 网页版解码器 / 桌面版命令行工具 | 浏览器解码器 | 两处要区分 |
| 缩略图 / 原图 | 缩略图、原图 | 原照、原始大图 | 指南统一 |
| PhotoData | PhotoData 文件夹 | PhotoData（单独指文件） | 它是文件夹 |
| 数据库 | PhotoDB / ArtworkDB 数据库 | PhotoData 数据库 | 两个名字都要出现 |
| 格式编号 | 格式编号 | 前缀（UI 里混用） | 指南统一为“格式编号” |
| 编码 | 编码（RGB555 等） | 编码格式 | 避免冗余 |
| 帧 | 帧 | 画面、图片帧 | 统一 |
| 单次导入 | 单次、单次最多 | 会话、批次 | session 不要译“会话” |
| 本地 / 本机 | 隐私承诺用“不会离开你的设备/不会上传”；技术说明用“本地” | 本机（营销页） | 不要三词混用 |
| 打包 | 打包下载、打包成 ZIP | 打包 ZIP | |
| 托管 | 由 Cloudflare 托管 / 托管在 Cloudflare Pages 上 | 托管在 Cloudflare（单独用） | 见第 4 节 |
| 开源 | 以 MIT 许可证开源 | 基于 MIT 许可证开源 | |
| 第三方声明 | 第三方声明 | 第三方通知 | |
| 隐私页标题 | 隐私政策与使用条款 | 隐私与条款（可作简称） | 建议全称 |
| 反馈 | 报告问题 / 提交 issue | 提问题（UI） | UI 统一“报告问题” |
| 赞助 | 请作者喝杯咖啡 | 打赏、捐赠 | 统一 |

## 11. 上线前检查清单

- [ ] 全站搜索“会话、批次、应用数据、变体、条目”是否还有残留？
- [ ] “打包 ZIP、写成 PNG、打开磁盘使用、只读文件、取回图片”这些搭配是否已修？
- [ ] 隐私页的承诺和指南 FAQ 是否矛盾（尤其是“恢复照片”）？
- [ ] 中英文版的浏览器支持、PhotoDB/ArtworkDB、共享（share）承诺是否一致？
- [ ] 语言切换、图片查看、ZIP 格式等 aria-label 是否统一且像人话？
- [ ] JSON-LD 里是否还有英文值（Requires JavaScript、All、Multimedia）？
- [ ] 随机抽 10 句给非技术中文读者读，能否一遍看懂？

## 12. 对照示例

| 英文原意 | 不要写 | 写成 |
|---|---|---|
| Local by default. | 默认留在本地。 | 默认只在本地处理。 |
| 0 bytes leave your device | 0 字节离开你的设备 | 文件不会上传 |
| Drop a file. Get the image. | 拖入文件，取回图片。 | 拖入文件，导出图片。 |
| Four formats, plus ZIP | 四种格式，还能打包 ZIP | 四种格式，还能打包成 ZIP |
| per session | 每次会话 | 单次 |
| Hosted by Cloudflare | 托管在 Cloudflare | 由 Cloudflare 托管 |
| as is, without warranty | 按现状提供，不作保证 | 按“现状”提供，不提供任何明示或默示的保证 |
