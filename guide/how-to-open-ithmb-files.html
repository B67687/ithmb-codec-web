Recovery guide

How to open .ITHMB files

.ithmb is the thumbnail cache Apple devices wrote for the photos and album art you synced with iTunes. The files live in PhotoData folders on old iPods and iPhones, and normal image viewers can't open them. This guide shows how to get the images out.

01 · Prepare

Before you start

What you need

  • An iPod that mounts as a disk (iPod Classic, Nano, and other disk-mode models) and its cable.
  • A Windows, Mac, or Linux computer, with disk use enabled in iTunes or Finder.
  • For iPhone or iPod Touch: a backup or a recovery tool. They don't mount as disks.

Copy the files and leave the device alone. Don't rename, move, or delete anything on it, and don't write to it. The decoder only reads.

Where the files live

This PC → iPod → iPod_Control/Photos/

Enable disk use in iTunes, then find the iPod under "This PC" and copy the PhotoData folder.

Finder → iPod → iPod_Control/Photos/

Enable disk use in Finder, then copy the PhotoData folder from the iPod.

Mounted iPod → iPod_Control/Photos/

Mount the iPod, then open iPod_Control/Photos/ in your file manager and copy the PhotoData folder.

Older models store thumbnails in Photos/Thumbnails/. Copy ArtworkDB from the same folder if you want the album art.

02 · Background

What is an ITHMB file?

Apple created ITHMB (short for iThumbnail) to store many small thumbnails in one file, so the device could browse a photo library without loading full-size originals. Some files hold raw pixels. Some wrap a JPEG. The format was never documented, which is why regular viewers can't open it.

These files usually turn up in PhotoData folders on old iPods and iPhones, or in a backup or recovered drive. They date from the iPod Photo and iPod Video era through the last iPod Classic, and from the first iPhone and early iPod Touch models. The decoder also accepts .ipm files.

You'll see three kinds of file:

  • F-prefix files such as F1019_1.ithmb: raw pixel data in an Apple-specific format, starting with a short format number.
  • T-prefix files such as T1024_1.ithmb: a JPEG image inside.
  • PhotoDB and ArtworkDB: database files that hold thumbnail entries. The image data is either inside the database or in separate .ithmb files.
01

Step one

Copy the files off the device

Connect the device, enable disk use, and copy the thumbnails to your computer. These files only exist on the device.

On an iPod Classic or Nano, connect it and enable disk use in iTunes on Windows or in Finder on Mac. Then copy the PhotoData folder from iPod_Control/Photos/ to your computer.

iPhone and iPod Touch don't mount as disks, so their files have to come out of a backup or a recovery tool. Either way, the decoder works on the files once they are on your computer.

What you need

The device, its cable, and disk use enabled in iTunes or Finder. For iPhone, a backup or a recovery tool.

What you'll see

A PhotoData folder of .ithmb files, plus ArtworkDB for album art.

If it fails

No photos? iPods store thumbnails, not originals. Try Photos/Thumbnails/ on older models or a backup for iPhone.

02

Step two

Open the decoder

The decoder runs entirely in your browser. Nothing to install, no account.

Go to ithmb-codec.dev/ithmb-decoder in a current browser (Chrome, Firefox, Safari, or Edge). It works the same on Windows, macOS, Linux, and phones.

What you need

A current browser. Chrome, Firefox, Safari and Edge all work.

What you'll see

The decoder page, with a drop area ready for your files.

If it fails

Try another current browser. Chrome, Firefox, Safari and Edge all work.

03

Step three

Drop the files and save the images

Each file appears as one image. Choose a format and save them, or download the whole batch.

Drag one file or many at once. Pick JPEG, PNG, BMP, or WebP for each image, or use Download all to save the batch as a ZIP. In the browser, each file must be 8 MB or smaller.

What you need

Files that carry their own image data. Limits: 8 MB per file and a session of 200 files and 256 MB. A ZIP over 100 MB asks for confirmation.

What you'll see

One image per file, a format switcher, and a Download all button.

If it fails

"Unknown format" usually means a raw PhotoData slot or a database file. See troubleshooting.

03 · Expectations

What you get back

Screen-sized thumbnails

The iPod saved thumbnails sized for its screen so it could browse a library without loading full-size files. A 320×320 thumbnail won't look as sharp as the photo you synced.

Reduced color on some models

Some models stored fewer colors in their thumbnail cache. What you decode is the file on the device, not a fresh conversion of the original.

Originals are elsewhere

These are thumbnails, not your original photos. The originals are in your photo library, backup, or wherever you imported them from.

04 · If it goes wrong

Troubleshooting

Most failures come from opening a file the browser doesn't support, or from a file that was cut off during copying.

"Unknown format" or a prefix of 0

The file doesn't carry its own image data. Raw PhotoData thumbnail slots only make sense with the PhotoDB or ArtworkDB database beside them, and the browser doesn't read those. For database files, use the desktop tools below.

The file is a database, not a single image

It's a PhotoDB or ArtworkDB database. It holds many thumbnails, not one image. Use the desktop command-line tool to open it (ithmb --open PhotoDB). Some ArtworkDB files keep their image data in separate .ithmb files, and that case isn't fully supported yet. If the output looks wrong, open an issue on GitHub with the file header or a sample.

The image is corrupt, cut off, or won't decode

The file may be truncated or damaged, or it may not be an .ithmb file at all. Copy it from the device again and check that its size matches the original.

No photos in PhotoData

iPods stored thumbnails, not originals. If the folder is empty, the photos may never have been synced, or they may be in the older Photos/Thumbnails/ path. On an iPhone or iPod Touch, look in a backup instead.

Colors look wrong

The file may use an encoding the decoder doesn't recognize yet. If the output still looks wrong, open an issue on GitHub with the file header or a sample so the project can look at the file.

Still stuck?

Bug reports and format samples are always welcome. Open an issue on GitHub(opens in a new tab) and we'll investigate.

For files the browser can't open, the project has desktop tools. The ithmb command-line tool reads a database with ithmb --open PhotoDB (or --open ArtworkDB) and writes each thumbnail as a PNG. Both are documented in the project's recovery guide(opens in a new tab). Some ArtworkDB files keep their image data in separate .ithmb files, and that case is still being fixed, so the output can look wrong. If it does, open an issue on GitHub with the file header or a sample. The --open argument is the database file itself, not the folder it sits in.

05 · Answers

Frequently asked questions

Can I convert multiple .ithmb files at once?

Yes. Drag multiple files into the decoder and it processes them all. Each file appears as one image, and Download all saves the batch as a ZIP.

Do my files leave my device?

No. Decoding runs in your browser, so files never leave your device. Nothing is uploaded. The privacy page explains this in more detail.

What about .ipm files?

The decoder accepts .ipm files too. It treats them like .ithmb files that carry their own image data.

Is this tool free?

Yes. There is no account, no ads, and no paywall. In the browser, each file must be 8 MB or smaller. A session is limited to 200 files and 256 MB. A ZIP over 100 MB asks for confirmation. If you'd like to support development, you can buy the author a coffee(opens in a new tab).

Why won't the files from my iPod's PhotoData folder open?

Some .ithmb files in PhotoData are raw thumbnail slots, not files that carry their own image data. They need the PhotoDB or ArtworkDB database in the same folder, and the browser decoder doesn't open those. For database files, use the desktop command-line tool (ithmb --open PhotoDB). Some ArtworkDB files keep their image data in separate .ithmb files. That case isn't fully supported yet, so the output can look wrong. If it does, open an issue on GitHub with the file header or a sample.

Can I get my original photos back?

No. These are the thumbnails the device made for its screen. The originals are in your photo library, backup, or the camera or memory card you imported them from.

Does one file contain one image?

The browser shows one image per file. Some raw files contain several frames one after another, and the browser shows the first. The command-line tool can pull out a specific frame with ithmb --frame N.

06 · Behind it

About the ITHMB Codec project

Ithmb-Codec is an open-source project that documents and decodes Apple's thumbnail formats. It maintains the decoder library, the browser app you are using, and format documentation for researchers and digital archivists.

Bug reports and format samples are always welcome. Open an issue on GitHub(opens in a new tab) and we'll take a look. If you find this useful, give the project a star on GitHub.
